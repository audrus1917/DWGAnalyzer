# Сравнение алгоритмов полнотекстового поиска: BM25, TF-IDF и Postgres

Источник: https://emschwartz.me/comparing-full-text-search-algorithms-bm25-tf-idf-and-postgres/
*Evan Schwartz, ноябрь 2024*

---

## BM25 vs TF-IDF

TF-IDF был основным алгоритмом ранжирования до появления BM25 (использовался в Lucene и
Elasticsearch до 2016 года). BM25 ввёл несколько ключевых улучшений:

1. **Насыщение частоты термина (saturation).** BM25 ограничивает влияние слов, которые
   повторяются очень часто: частота важна, но только до определённого предела. TF-IDF такого
   ограничения не имеет — многократные повторения слова бесконтрольно увеличивают итоговый балл.

2. **Нормализация по длине документа.** BM25 учитывает, что длинный документ просто по факту
   своего объёма содержит больше повторений слов. TF-IDF длину документа, как правило, не
   учитывает, что смещает результаты в пользу длинных текстов.

3. **Сглаженный IDF.** BM25 сглаживает обратную документную частоту для очень
   распространённых и очень редких слов — TF-IDF этого не делает, что даёт нестабильные
   результаты на обоих крайних значениях.

4. **Настраиваемые параметры.** BM25 имеет два параметра: `k1` — степень насыщения TF, и
   `b` — степень нормализации по длине. TF-IDF параметров не имеет: он проще, но менее гибок.

5. **Теоретическая база.** BM25 построен на основе *Probabilistic Relevance Framework* —
   строгой вероятностной теории. TF-IDF — набор эвристик, которые на практике оказались
   неплохими.

## BM25 vs Postgres full-text search

Встроенный полнотекстовый поиск Postgres проще и слабее BM25:

| Аспект                    | BM25                                    | Postgres                                                            |
|---------------------------|-----------------------------------------|---------------------------------------------------------------------|
| Фильтрация незначимых слов | IDF — на основе всей коллекции          | Стоп-слова из языковых словарей                                     |
| Ранжирование              | TF с насыщением + IDF (редкость)        | `ts_rank` — TF без насыщения; `ts_rank_cd` — TF + близость слов    |
| Нормализация длины        | По среднему длине по всей коллекции     | По умолчанию отсутствует; опции не используют данные по корпусу     |

**Вывод:** качество поиска в Postgres хуже, чем при BM25, но для систем, где уже используется
Postgres и простота важнее точности, это приемлемо.

**Альтернатива:** расширение [pg_bm25 (ParadeDB / pg_search)](https://www.paradedb.com/blog/introducing_search)
добавляет ранжирование по BM25 прямо в Postgres и, по бенчмаркам, работает значительно быстрее
встроенного поиска.

Что Сейчас Умеет parsedwg

Вариант 2. Деловой для презентации или ТЗ
=========================================

parsedwg представляет собой систему обработки проектной документации
в форматах DWG/DXF с сохранением результатов в структурированную базу
данных. Решение автоматически обходит каталоги проектов, извлекает из
чертежей геометрию, блоки, слои, тексты, табличные данные и связи между
сущностями, а также поддерживает загрузку сопроводительных документов.
На основе этих данных система обеспечивает поиск, анализ состава проекта,
контроль полноты извлечения, экспорт результатов и AI-интерпретацию имен
и объектов.

Платформа уже закрывает ключевые задачи цифровизации проектной
документации: инвентаризацию чертежей, структурирование содержимого
DWG/DXF, извлечение табличных блоков, подготовку данных для аналитики и
RAG-сценариев, а также семантическое обогащение сущностей с помощью LLM.
Это делает parsedwg не просто парсером, а прикладным инструментом для
накопления, поиска и осмысления инженерных данных проекта.


Вариант 3. Технический с перечислением CLI-возможностей
=======================================================

parsedwg умеет рекурсивно обрабатывать каталоги с DWG/DXF и ZIP-архивами,
конвертировать DWG в DXF через ODA File Converter, извлекать layouts,
layers, blocks, primitives, координаты, текст и табличные блоки, а затем
сохранять дерево сущностей в PostgreSQL. Дополнительно система загружает
документы PDF/DOCX/XLSX/CSV в БД для последующего поиска и
RAG-использования.

Через CLI уже доступны основные рабочие сценарии:

1. ``process``: рекурсивная загрузка дерева файлов и сущностей в БД,
   включая AI-теги имен.
2. ``extract-name-tags``: извлечение смысловых тегов из имен файлов и
   папок в JSON.
3. ``extract-token-tags``: AI-расшифровка инженерного смысла токенов из
   имен слоев, файлов и блоков.
4. ``extract-name-meaning``, ``explain-block``, ``interpret-entities``,
   ``interpret-blocks``, ``interpret-block``: интерпретация имен сущностей
   и блоков через LLM.
5. ``categorize-entities``: AI-категоризация сущностей с записью
   результата в БД.
6. ``search``, ``index``, ``ask``: полнотекстовый, векторный и гибридный
   поиск с RAG-ответами.
7. ``file-stat``, ``file-stat-from-db``: сбор статистики по файлу и по
   данным, уже загруженным в БД.
8. ``export-block-png``, ``export-block-svg``: экспорт отдельных блоков в
   графические форматы.
9. ``export-blocks-xlsx``, ``export-blocks-table``: выгрузка блоков и
   табличных данных в XLSX и текстовый вид.
10. ``verify-extraction``: сверка содержимого исходного файла с тем, что
    записано в БД.
11. ``project-add``, ``project-update``, ``project-delete`` и
    ``category-add``, ``category-update``, ``category-delete``,
    ``category-list``: управление проектами и семантическими категориями.

Задача
======

Описание, как это (почти) сейчас работает
==========================================

В этой задаче объектом для получения данных является такая древовидная структура:

* основной каталог;
* подкаталоги первого уровня, названия которых определяют подсистему (водоснабжение, водоотведение, 
  теплоснабжение, электроснабжение);
* подкаталоги, которые содержат:
  - файлы с чертежами, которые содержат:
    - графичекие примитивы (линии, дуги, окружности, тексты и т.д.);
    - блоки, которые могут содержать графические примитивы и другие блоки;
    - для всего определяются `layers`, задающие цвет, тип линии, толщину и т.д.;
  - `xlsx` и `xlsm` файлы, которые содержат табличные данные;
  - `docx`, но там по большей части титульные листы и т.п.

Есть уже разработанный парсер для получения и сохранения данных из чертежей и табличных данных 
(PostgreSQL + pgvector). Что делает:

* для заданного в качестве параметра каталога или файла конвертирует несколькими процессами файлы чертежей
  в формат DXF, во временные файлы;
* парсит эти файлы и сохраняет данные в базу данных всю эту древовидную структуру:
  
    каталог -> подкаталог подсистемы -> файлы с чертежами -> layouts -> графические примитивы и блоки, cвязанные с ними `layers`;

* для блоков определяется, являются ли они таблицей с данными, и если да, то сохраняются данные из этих блоков 
  в JSONB;
* для блоков сохраняется значимый текст (если там только текст вида "1067", то не сохраняется).

Названия подкаталогов и файлов пробуем лемматизировать, чтобы смысл какой-то достать.

Также каталоги подсистем содержат подкаталоги с изменениями вида `Изм 0`, `Изм 1` и т.д., в которых 
хранятся файлы чертежей с изменениями. Эти изменения тоже парсятся и сохраняются, но с пометкой, что это 
изменения, и с указанием номера и даты изменения.

В PostgreSQL добавлен pgvector и расширения для BM25+, чтобы можно было делать полнотекстовый 
поиск по тексту и векторный поиск по векторным представлениям.

Как это все можно применить?

Ответы от Copilot и LLM


Поиск по проектной документации
---------------------------------

* Полнотекстовый поиск (BM25+) по тексту блоков, названиям слоёв и подкаталогов —
  найти «где упоминается насос типа Х» или «какие чертежи касаются вентиляции 3-го этажа».
* Векторный поиск (pgvector) по семантически близким запросам —
  «найди чертежи, где описывается аварийное отключение».

Навигация и инвентаризация
---------------------------

* Построить интерактивный каталог чертежей с фильтрами по подсистеме, этажу, разделу.
* Показать историю изменений по каждому чертежу (``Изм 0``, ``Изм 1``…) и что именно
  изменилось в блоках.

Анализ комплектности
---------------------

* Проверить, что для всех подсистем и этажей есть чертежи.
* Выявить чертежи без табличных данных или без лемматизируемых тегов в имени —
  потенциально плохо именованные или неполные.

Извлечение спецификаций
------------------------

* Блоки-таблицы (JSONB) содержат спецификации оборудования. Можно агрегировать
  оборудование по типу, подсистеме, этажу и экспортировать в xlsx.

RAG-интерфейс для вопросов к проекту
--------------------------------------

* Подключить LLM поверх гибридного поиска (BM25 + vector). Задавать вопросы вида
  «какое оборудование установлено на 4–5 этажах в системе водоснабжения?» и получать
  ответ со ссылкой на чертёж.

Обнаружение несоответствий / контроль качества
------------------------------------------------

* Сравнить слои из разных версий одного чертежа.
* Найти блоки с одинаковыми именами, но разными атрибутами в разных подсистемах —
  потенциальные расхождения.

Дашборды и метрики проекта
---------------------------

* Количество чертежей, блоков, изменений по подсистемам.
* Прогресс: сколько подсистем полностью распарсено, сколько файлов не удалось сконвертировать.

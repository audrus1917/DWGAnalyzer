# AGENTS.md

## Назначение

Эта инструкция задает рабочий режим для агентных правок в репозитории parsedwg,
в первую очередь для задач по разбору структуры каталогов с чертежами и извлечению
смысловых тегов из имен файлов.

## Контекст текущей задачи

Ниже зафиксировано постфактум, что уже реализовано и как с этим работать дальше:

- В CLI добавлена команда extract-name-tags.
- Команда обходит каталог рекурсивно и формирует JSON с сущностями и токенами.
- Для сущности Этаж поддержаны формы: этаж, этажа, этажей, эт, эт.
- Для Кровли поддержаны формы: кровля/кровле/кровли и крыша/крыше/крыши.
- В list-layouts добавлен вывод layers для каждого layout.
- В описании DXF-сущностей добавлен вывод координат по всем точечным атрибутам.
- Для INSERT в описании выводится имя вставляемого блока.

## Область изменений

При похожих задачах в первую очередь проверять и править:

- src/parsedwg/name_tags.py
- src/parsedwg/cli.py
- src/parsedwg/explorer.py
- tests/test_name_tags.py
- tests/test_cli_list_commands.py
- tests/test_cli_table_export.py

## Правила реализации

- Сохранять существующие публичные API и формат CLI, если это не отдельная цель задачи.
- Изменения делать минимальными, без лишнего рефакторинга.
- Для новых регулярных выражений добавлять тесты на граничные случаи.
- Для русских словоформ учитывать варианты с сокращениями и пунктуацией.
- Для распознавания диапазонов этажей учитывать разделители -, –, запятые, союз и.
- Не полагаться только на границы слова для чисел после символа подчеркивания.
- Для DXF-координат использовать фактические атрибуты сущности, а не только insert.
- Для обхода слоев в layout учитывать вложенные INSERT и защищаться от циклов блоков.

## Проверки перед завершением

Всегда запускать:

1. ./.venv/bin/pytest -q
2. PYTHONPATH=src ./.venv/bin/python -m parsedwg --help
3. При изменении name-tags:
   PYTHONPATH=src ./.venv/bin/python -m parsedwg extract-name-tags _data/tower_A -o _logs/tower_A_name_tags.json

Задача считается завершенной, если:

- Реализация покрыта тестами в tests/.
- Тесты проходят локально.
- CLI-команда работает на реальных входных данных из _data/.

## Строгий CI Policy

Этот раздел применять для merge-request и релизных правок.

### CI Gate (обязательно)

Изменение считается непроходным, если не выполнено хотя бы одно из условий:

1. Все тесты прошли:
   ./.venv/bin/pytest -q
2. CLI запускается и выводит help без ошибок:
   PYTHONPATH=src ./.venv/bin/python -m parsedwg --help
3. Для изменений в name-tags подтверждена работа на реальном каталоге:
   PYTHONPATH=src ./.venv/bin/python -m parsedwg extract-name-tags _data/tower_A -o _logs/tower_A_name_tags.json
4. Нет новых ошибок линтера/типизации в затронутых файлах.
5. Diff содержит только релевантные изменения задачи.

### Обязательный Code Review Checklist

Перед одобрением ревьюер проверяет:

1. Обратная совместимость CLI:
   Имена команд и ключей не изменены без отдельной договоренности.
2. Корректность regex для русских словоформ:
   Учтены сокращения, пунктуация и пограничные случаи.
3. Покрытие тестами:
   Для новых/измененных правил парсинга есть как минимум один позитивный и один
   граничный тест.
4. Детерминированность результата:
   Порядок коллекций в JSON стабилен (сортировка там, где это важно).
5. Безопасность обхода DXF-структур:
   Для вложенных INSERT есть защита от циклов.
6. Наблюдаемость:
   При падении команды сообщение об ошибке позволяет локализовать проблему.

### Merge Blockers

Изменение не мержится до исправления, если:

- Падает хотя бы один обязательный тест.
- Есть регресс по формату CLI/JSON без согласованного миграционного шага.
- Добавлены нерелевантные изменения или массовый рефакторинг вне задачи.
- Нет теста на баг, который был исправлен в этой задаче.
